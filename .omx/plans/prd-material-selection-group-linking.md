# PRD：材料选择分组联动一致性

## 问题

当前动态追加、重新展开与排序都会调用全量 `RebuildProcessGroups`，普通分组被重新创建为未锁定组；分组表格未接入拖放；全局预设菜单对动态左侧子控件的抑制边界不完整。

## 实施方案

1. 将全量初始建组、增量追加、排序和渲染明确分开：仅首次 `SetPendingFiles` 使用全量构建；追加保留 `_processGroups`，所有新文件只进入 `_processGroups` 显示顺序中第一个 `!IsLocked && !IsPreserveGroup` 的联动组，不改变任何锁定组；若无合格组，则在末尾创建一个继承当前右侧选择参数的未锁定、非保留联动组。展开只渲染，排序只按 `_batchItems` 的目标顺序重排各既有组的 `Items`，分组顺序不变。
2. 提供原子化的跨组移动方法：在首次集合修改前校验源组、目标组、两端锁定状态及全部文件归属；任一校验失败立即拒绝。
3. 为每个分组 `DataGridView` 连接拖放事件，载荷只包含发起表格内选中的文件与源组标识，并调用原子移动方法。
4. 修复 `WM_CONTEXTMENU` 的左侧区域判定：基于消息来源控件/焦点与面板后代关系抑制全局预设菜单，同时保留左侧专属数量菜单。
5. 添加以公开/内部可测试方法为边界的回归测试，避免依赖鼠标自动化证明业务状态转换。

## 风险与缓解

- 重建与追加路径混用：保留 `SetPendingFiles` 的初始全量构建，仅改变 `AppendPendingFiles` 的增量路径。
- 跨组移动发生部分更新：所有锁定与归属校验必须在第一次集合修改前完成。
- 空组删除导致目标引用失效：移动完成后再删除空的未锁定源组，不删除目标组。
- 全局菜单消息坐标与动态子控件命中差异：同时覆盖鼠标消息和键盘焦点路径，使用“是否属于 `pnlFileList` 后代”而非单一静态边界推断。
- 拖放过程中重新渲染导致载荷过期：载荷仅保存源组 ID 和文件路径；落下时重新从当前模型解析并完成全部校验。
- `_processGroups` 与 `_batchItems` 出现重复或缺失：状态转换后以文件路径唯一性和双向归属一致性断言验证；任何校验失败不修改集合。
- 源组或目标组在落下前被删除/锁定：落下时重新查找并检查两端状态，不信任拖动开始时的对象引用。
- 键盘触发 `WM_CONTEXTMENU` 没有鼠标坐标：从当前焦点控件向上判断是否属于左侧面板；鼠标路径同时结合消息来源和客户区命中。

## 方案比较

- 增量更新（采用）：保留现有对象身份，仅对新增项和明确移动项做原子变更。复杂度中等，最符合锁定语义，回归面最小。
- 身份保持的全量协调：重新计算候选分组，再按业务键匹配旧组并迁移状态。能保留分类能力，但键冲突和成员差异处理复杂，容易误合并。
- 重建后状态回映射：沿用当前重建，再按旧 `GroupId`/参数复制锁定状态。改动表面最小，但新 ID、空组及同参数多组会造成歧义，无法可靠保持成员身份。

采用增量更新；首次加载仍保留现有全量分类算法，避免扩大本次修复范围。

## 执行顺序

1. 先新增失败的状态转换测试。
2. 修复增量分组分配与锁定保持。
3. 实现原子跨组移动并连接 UI 拖放。
4. 修复全局预设菜单在左侧区域的抑制边界。
5. 运行目标测试、完整测试、Debug 构建并审查差异。
